# Self-contained fixed-impulse evaluation report contract

This slice stores one completed `evaluate_route` trial as a dedicated version-1 JSON report, distinct from the screened `start_mission` study report. The report carries the exact runtime snapshot bytes as a JSON string, their lowercase SHA-256, the submitted protocol-v1 request, and the observed worker event stream in order. The embedded bytes make the source independently reloadable without a local KSP path. The report labels the result `independent_nbody_fixed_impulse_checkpointed_only` and records both route-seed revalidation and continuous Mars-stay verification as false. It never says feasible, optimized or Principia-equivalent.

Composition and reload must enforce a 16 MiB source cap, recompute the exact-byte hash, parse the runtime snapshot, and match request source hash, inertial frame and state epoch to that snapshot. The request must be `evaluate_route` with runtime source mode and a nonempty request ID. Its trial must identify the four distinct source body roles, use the source hash and `runtime_observed_uncompared` confidence, include exactly four impulses and four checkpoint targets, and have strictly ordered dates with exactly 5,184,000 SI seconds between Mars arrival and departure. Reject atmosphere overrides and a fabricated source-confidence claim. The path used when submitting the request is historical metadata; reload relies on the embedded bytes.

Replay every stored event through the fixed-impulse `WorkerEventValidator` with the request ID and source identity. Require started, zero then finished progress, and one `complete` terminal event; cancelled, error, client_error, missing, reordered, duplicate or post-terminal events cannot be saved as a completed report. The existing client validator covers the four ordered SI burns and checkpoints, positive Venus safety margin, Mars radius diagnostics, cross-pass same impulses and disagreement, and charged total. Also bind the completed role IDs, burn epochs and vectors, frame/epoch, and source identity to the stored trial and embedded snapshot. Compare checkpoint residuals and reported disagreements with the trial's explicit acceptance tolerances; compare the Venus event time/radius/safety with the requested window and max radius and the source's atmosphere boundary; compare Mars radius diagnostics with the requested parking interval. These are internal consistency checks, not numerical proof. Report validation does not rerun the numerical integration.

Cap the entire serialized report at 32 MiB and the event stream at 16 entries before parsing or replaying; reject excess instead of truncating silently. The exact embedded source remains capped at 16 MiB.

Before implementation, observe rejection of wrong kind/version, changed source bytes or hash, mismatched request/terminal identity, swapped trial roles or impulses, out-of-tolerance residuals, wrong fixed stay, missing or reordered progress, unsafe Venus event, false evidence flags, excessive report/event size, and cancelled/partial results. A positive manufactured runtime-shaped fixture must save and reload identically, with a prior valid report left intact after a rejected replacement. Validate on Ubuntu and Windows. These are serialization and protocol checks, not installed-game comparison or rendered GTK acceptance.
