# Self-contained fixed-impulse evaluation report contract

This slice stores one completed `evaluate_route` trial as a dedicated version-1 JSON report, distinct from the screened `start_mission` study report. The report carries the exact runtime snapshot bytes as a JSON string, their lowercase SHA-256, the submitted protocol-v1 request, and the observed worker event stream in order. The embedded bytes make the source independently reloadable without a local KSP path. The report labels the result `independent_nbody_fixed_impulse_checkpointed_only` and records both route-seed revalidation and continuous Mars-stay verification as false. It never says feasible, optimized or Principia-equivalent.

Composition and reload must enforce a 16 MiB source cap, recompute the exact-byte hash, parse the runtime snapshot, and match request source hash, inertial frame and state epoch to that snapshot. The request must be `evaluate_route` with runtime source mode and a nonempty request ID. Its trial must identify the four distinct source body roles, use the source hash and `runtime_observed_uncompared` confidence, include exactly four impulses and four checkpoint targets, and have strictly ordered dates with exactly 5,184,000 SI seconds between Mars arrival and departure. Reject atmosphere overrides and a fabricated source-confidence claim. The path used when submitting the request is historical metadata; reload relies on the embedded bytes.

Replay every stored event through the fixed-impulse `WorkerEventValidator` with the request ID and source identity. Require started, zero then finished progress, and one `complete` terminal event; cancelled, error, client_error, missing, reordered, duplicate or post-terminal events cannot be saved as a completed report. The existing client validator covers the four ordered SI burns and checkpoints, positive Venus safety margin, Mars radius diagnostics, cross-pass same impulses and disagreement, and charged total. Report validation does not rerun the numerical integration.

Before implementation, observe rejection of wrong kind/version, changed source bytes or hash, mismatched request/terminal identity, wrong role or fixed stay, missing or reordered progress, unsafe Venus event, false evidence flags, and cancelled/partial results. A positive manufactured runtime-shaped fixture must save and reload identically, with a prior valid report left intact after a rejected replacement. Validate on Ubuntu and Windows. These are serialization and protocol checks, not installed-game comparison or rendered GTK acceptance.
