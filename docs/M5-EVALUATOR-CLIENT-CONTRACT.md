# Fixed-impulse worker-client boundary

The GTK process bridge currently validates `start` screened seeds and `start_mission` screened routes. This slice adds a third result kind for the headless `evaluate_route` command. The client does not start an evaluation from the GTK form yet; it must accept a valid versioned event stream and reject a malformed one before any result reaches the UI. Numerical acceptance remains owned by `RouteEvaluate`, not by JSON shape checks.

The fixed-impulse kind requires protocol version 1, exact request ID, exact runtime snapshot hash and `runtime_observed_uncompared` confidence after source acceptance. A pre-source error may lack identity. A source-bound cancellation may arrive before `started`; it must remain terminal. `started` supplies SI units, inertial frame labels, explicit state epoch and the `independent_nbody_fixed_impulse_checkpointed_only` label. Progress is one bounded phase with monotonic `completed_phases` from zero to one; screened-search cell counters and candidate/route/refinement events are invalid for this kind. A `complete` event must preserve the started frame/epoch/source identity, say `newtonian_point_mass`, retain both evidence flags as false, and carry four named role IDs.

For each coarse and strict pass, validate exactly four ordered burns with finite three-component SI impulse vectors, finite nonnegative magnitudes consistent with those vectors, and the same four burn epochs across passes. Validate four ordered named checkpoints (launch, Mars capture, Mars pre-departure, home return capture) with their burn-side epochs and finite nonnegative residuals; preserve the exact 5,184,000 SI-second Mars stay. Validate a Venus event with the mapped Venus body ID, finite UT/distance/clearance, and a positive source-bound safety margin. Validate finite ordered Mars radius diagnostics and finite nonnegative disagreement metrics. Sum the four coarse burn magnitudes and compare with `total_charged_delta_v_mps` within a declared floating-point tolerance. These checks reject contradictory event data; they do not certify physical truth or continuous parking.

Before implementation, test observable rejection of: wrong kind, source identity, frame/epoch/units/force model or label; fabricated candidate/route events; progress regression; duplicate/late terminal event; missing or reordered burns/checkpoints; inconsistent burn norm/total; false evidence flags; wrong Venus body or unsafe margin; nonfinite residual/radius/disagreement; and absent required fields. A valid fake worker process must deliver started/progress/complete without UI-thread blocking. Cancellation and premature EOF must remain bounded and reaped by the existing process bridge. The new mode must not loosen validation for screened seeds or routes.

Headless validation here does not prove an actual JNSQ/Principia runtime capture, solver agreement, rendered GTK behavior, or a distributable package.
