# M6 route assembly contract

Specified before implementation. A first route-screening slice joins three dated M4 leg seeds: home → Mars-role arrival/capture, a fixed 5,184,000 SI-second parking-orbit stay, Mars-role departure → Venus-role arrival, and an unpowered Venus-role flyby → home return. The role names map to explicit imported body IDs; `JNSQKerbin`, `JNSQDuna` and `JNSQEve` appeared in the disposable load log, but no flight snapshot has yet confirmed their dynamical states. Never substitute Earth/Mars/Venus solar-system data for JNSQ Reborn.

All leg seeds must share an analysis-ready snapshot hash, source confidence, right-handed inertial axes, central body, planetary ephemeris identity and independent Newtonian force label. Treat each supplied seed as untrusted: verify its dated endpoint states, Lambert geometry and residuals against the supplied ephemeris before assembling a route. Retain the freshly solved velocities, residuals and derived v∞ values in the route so tolerated input rounding cannot change burns or flyby geometry. Departure/arrival dates and flight times must be finite, positive, increasing, consistent, and inside ephemeris coverage. Compare the actual Mars-role arrival-to-departure gap directly with 5,184,000 seconds using one declared absolute time tolerance. Venus-role arrival and flyby departure must use the same exact encounter UT when forming planet-relative vectors. The total route duration obeys the request cap. Incompatible source/frame/time states, duplicated roles, unknown atmosphere boundaries, nonpositive radii/gravity, invalid altitudes or unbounded input combinations fail visibly before ranking.

For a circular parking orbit at radius `r_p = body radius + parking altitude`, the patched-conic impulse estimate is `sqrt(v_inf² + 2 μ/r_p) - sqrt(μ/r_p)` in m/s. Report home injection, Mars capture, Mars departure and home return capture separately, with departure and return C3 = `v_inf²` in m²/s². These are optimistic screening estimates: plane changes, parking-orbit phasing, corrections, ascent/descent and finite burns are excluded and named. An entry return is not supported by this first slice and must be rejected rather than priced as zero. The fixed stay is a parking-orbit stay, not a surface stay.

For the Venus-role flyby, form incoming and outgoing planet-relative velocity **vectors** at the shared encounter UT, then use the M4 unpowered screen with explicit atmosphere height, minimum safety margin, maximum periapsis and asymptotic speed-mismatch tolerance. Reject a zero turn, incompatible speeds, unsafe minimum periapsis and turns that exceed available bending. No hidden powered flyby burn is allowed. The route is labeled `patched_conic_screened_route`, never `feasible`, `optimized`, `Principia-equivalent` or `runtime_verified` solely from this assembly.

Before implementation, observe failures for wrong role order, fabricated or geometrically impossible legs, stay and flyby time mismatch, nonpositive flight time, speed mismatch, unsafe flyby, unknown atmosphere, invalid parking altitudes, source mismatch, excessive candidate combinations, and no route in the requested window. A positive synthetic fixture must derive its leg seeds from a valid solver and check the four burn components and C3 against independent closed-form calculations. Deterministic bounded top-K ranking must retain at most K routes during enumeration; repeated input must give the same result. M6 acceptance still needs n-body refinement of all legs and assists, constraint margins, an independent tighter repropagation, genuine loaded-state comparison, and a mission report.
