# Mission study and report contract

Specified before implementation. A saved study is versioned UTF-8 JSON containing: the exact runtime snapshot SHA-256 and confidence, the runtime exporter/game/save/capture identity when available, inertial frame and state epoch, independent ephemeris force model/integrator/settings and measured fit errors, named role mapping, every SI-second date/flight grid and constraint, the 5,184,000-second parking stay, and the final ranked `patched_conic_screened_route` results with three dates, four separate parking burns and flyby margins. Each route carries its stable ID and its validation status. The no-leap calendar label is display-only, with the mapping and day length recorded separately from UT.

Save through a temporary file in the destination directory and replace the destination only after the complete JSON is flushed. Reload validates schema version, finite numbers, result labels, required source/frame/epoch fields, route count and identity uniqueness. A loaded report is historical evidence: it must not silently become a fresh runtime observation or a Principia-equivalent prediction. The UI must identify the source snapshot by exact hash and ask for that file before rerunning an analysis. An explicitly synthetic study remains synthetic after save/reload.

Observe before implementation: missing/unsupported version, truncated JSON, nonfinite values, wrong or missing source identity, duplicate route IDs, altered burn total, inconsistent leg/stay dates, unsafe flyby claimed feasible, and failed replacement preserving the previous file. Positive tests round-trip a synthetic screened route with identical SI values, provenance and status. This report does not establish n-body feasibility or installed-game comparison; those require separate validation fields with evidence references.
