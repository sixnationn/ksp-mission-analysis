# Fixed-impulse worker checkpoint

The `evaluate_route` protocol-v1 command accepts one explicit fixed-impulse trial. It reads a runtime snapshot file with a 16 MiB cap, verifies its exact SHA-256, rereads the same number of bytes to detect in-place changes, and passes the original verified bytes to `evaluate_fixed_route_runtime`. Atmosphere boundaries come from that source. The route seed supplies only body roles and absolute SI-second dates; the caller supplies the actual parking state, four impulses, four body-relative targets, and all evaluation tolerances. The response remains `independent_nbody_fixed_impulse_checkpointed_only`, with route-seed evidence and continuous Mars parking both false.

Before implementation, a missing-source request failed its pre-`started` rejection test. The final MSYS2 UCRT64 worker executable passed **167 checks**, focused MSVC CTest passed **1/1**, and the full MSYS2 UCRT64 CTest suite passed **12/12**. A cancellation before or after numerical work emits one terminal event. Direct CLI request and cancellation lines are capped at 1 MiB, and request IDs at 128 bytes; an actual oversized input produced one `request_too_large` error and exited.
