# Fixed-impulse evaluator worker gate

The next headless slice exposes the existing `evaluate_fixed_route_runtime` calculation through the one-request JSON-lines worker. It accepts a **single explicit fixed-impulse trial**, not an optimizer result. The caller supplies a screened route only as a date and body-role seed, a home parking state, four three-component SI impulse vectors, four body-relative target states, and the evaluator's separate ephemeris, spacecraft, parking, Venus and coarse/strict budgets. The worker must never synthesize a parking state from a body-centre Lambert endpoint or relabel the trial as Principia-matched.

`evaluate_route` uses protocol version 1 and one `request_id`. The source is an exact-byte runtime snapshot path plus lowercase SHA-256, expected inertial frame and state epoch. Reuse the worker's 16 MiB bounded read, before/after source-change checks and runtime reader; the evaluator must receive the **same bytes** that passed the hash check. The source supplies all atmosphere boundaries. Reject an atmosphere override or a synthetic/source-confidence claim in the submitted trial. A test-only synthetic mode may use a fixed manufactured fixture, and must remain visibly `synthetic_fixture`.

The route seed carries exact body IDs for central/home/Mars/Venus, launch, Mars arrival, Mars departure, Venus expected encounter and home return UT, fixed stay of 5,184,000 SI seconds, and the source hash/confidence. The adapter constructs the internal `ScreenedRoute` fields that the evaluator validates. Untrusted Lambert residuals, cost, turn-angle and C3 fields must not affect the fixed-impulse outcome. The worker returns the evaluator's current label, `independent_nbody_fixed_impulse_checkpointed_only`, with `route_seed_evidence_revalidated=false` and `mars_stay_continuously_verified=false` until their separate gates pass.

Emit `started` only after bounded source and request validation, then bounded `progress` phases, and exactly one terminal `complete`, `cancelled` or `error`. `complete` includes source hash/confidence, SI/frame/epoch, four actual burn magnitudes and total charged delta-v, each named checkpoint's residuals, the actual Venus closest event and safety margin, Mars radius diagnostic, and separate coarse/strict disagreement metrics. Reuse the worker client's line-size and queue limits when wiring UI later. Cancellation is checked before and after each non-interruptible numerical evaluation; an in-progress integration may require the existing client timeout/child termination path. Never emit a partial evaluation as a passed result.

## Observable failures before implementation

- Reject malformed/missing vectors, nonfinite numbers, unbounded settings, wrong frame/epoch, stale hash, changed source bytes, synthetic confidence masquerading as runtime, and caller-supplied atmosphere overrides before `started`.
- Reject a body-centre launch, changed fixed-stay dates, extra or hidden impulse, unsafe Venus or parking encounter, missing true Venus closest event, and strict-run disagreement with a terminal error and no `complete`.
- A cancellation before numerical work ends with `cancelled`; cancellation after a completed fixed evaluation cannot create a second terminal event. Worker process exit must not hang on its input reader.
- A manufactured positive trial must round-trip through the worker and report its four actual burns, named SI checkpoints, exact source identity, explicit partial label and both false evidence flags. The same trial with altered exact source bytes or an unsafe interior Mars-radius fixture must fail.

Headless worker tests establish protocol and deterministic numerical wiring only. Runtime JNSQ/Principia state capture, continuous Mars stay, optimization, rendered GTK behavior, and installed-game comparison remain separate gates.
