# Fixed-impulse worker-client validation

The headless `WorkerClient` now accepts the versioned `evaluate_route` event stream as a `fixed_impulse_evaluation` result. It validates source identity, runtime confidence, SI units, inertial frame and state epoch, a monotonic one-phase progress sequence, and one terminal event. Its complete-event checks cover the four ordered burns and named checkpoints, exact 5,184,000-second Mars stay, mapped Venus event and positive safety margin, Mars radius diagnostics, coarse/strict agreement on the prescribed impulses, nonnegative disagreement metrics, and charged burn total. The existing screened-seed and screened-route kinds retain their own event rules.

The observable pre-implementation failure was that a valid evaluation `started` event was rejected as `total_cells invalid`: the client only understood screened searches. Tests now exercise a valid fake worker process plus rejection of malformed source, frame, epoch, units, force model and label; fabricated screened-search events; progress regression and incomplete progress; duplicate or late terminal events; missing or reordered burns and checkpoints; inconsistent impulse vectors, magnitudes or charged total; coarse/strict impulse disagreement; incorrect Venus role or unsafe margin; nonfinite residual, radius and disagreement fields; and absent required fields. Premature EOF and pre-start cancellation are bounded process cases. A missing `burns` field previously escaped as a JSON-library exception and now produces a classified `WorkerClientError`.

Local evidence: the focused MSYS2 UCRT64 executable passed **112 worker-client checks**; the focused MSVC Debug CTest passed **1/1**; the full MSYS2 UCRT64 CTest suite passed **12/12**. The fake worker verifies process and protocol behavior without a GTK window. The terminal payload is synthetic runtime-shaped data: these checks do not establish JNSQ/Principia state agreement, physical feasibility, continuous Mars parking, or rendered UI behavior. The GTK study form does not yet issue `evaluate_route` requests.
