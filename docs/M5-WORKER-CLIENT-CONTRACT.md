# M5 worker process bridge contract

Specified before implementation. The GTK desktop must run `ksp_worker` as a separate child process without a shell, send one versioned JSON-line request, read newline-delimited events without blocking the GTK thread, and send a matching versioned cancellation line on request. The worker executable path is explicit (normally beside the desktop executable); a missing or non-executable path produces a visible error. This bridge does not change numerical code or make synthetic seeds into runtime-verified results.

Validate an event stream before it reaches the UI: strict JSON object, protocol version 1, exact request ID, allowed event type, monotonically nondecreasing bounded progress, and matching exact snapshot hash/source confidence on every post-load event. Pre-load error events may lack source identity and must remain errors. Limit each event line to 1 MiB and the retained event queue to a bounded count; reject malformed, oversized, contradictory or cross-request events rather than drawing them. Preserve final ranked candidate order and labels. Do not trust a candidate event as a final ranked result. EOF before a terminal `complete`, `cancelled` or `error` is a worker failure. Include stderr/exit status in a bounded diagnostic without exposing arbitrary file contents.

Cancellation must send the matching control message, keep the UI responsive, and escalate to process termination after a bounded deadline if the worker does not stop. The client must reap the process and its I/O threads on normal completion, cancellation and owner destruction. A child process must not survive a closed study window. The UI should dispatch parsed events to the GTK main context; worker reads and waits remain off that thread. A runtime source stays `runtime_observed_uncompared`; a synthetic source stays `synthetic_fixture`.

Before implementation, observe failures for missing worker executable, malformed/oversized line, wrong protocol/request/source identity, progress regression, premature EOF, nonzero exit, worker that ignores cancellation, and second start while one child is active. A valid local `ksp_worker` run must deliver ordered started/progress/final events; cancellation must end with a terminal status and leave no child. Headless bridge tests establish process/protocol behavior only. Rendered GTK responsiveness and normal-size visual review remain separate M5 acceptance evidence.
