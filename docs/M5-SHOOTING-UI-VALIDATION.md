# M5 bounded-shooting GTK workflow validation

The observable failures in `M5-SHOOTING-UI-CONTRACT.md` were specified before implementation on 23 September 2026. The new headless workflow tests were red before production changes for missing helper symbols, unsupported status and a hidden atmosphere override.

The right pane now offers **Shoot nearby trial** beside fixed-trial evaluation. It requires the same advanced four-impulse trial JSON plus an explicit per-impulse cap, finite-difference impulse, iteration cap and probe cap. The headless helper reopens and rehashes the imported runtime source, checks route-seed provenance, fixed dates and 5,184,000 SI-second Mars stay, four finite impulses and targets, hidden source/atmosphere fields, and request size before the child starts. The worker remains authoritative for the full trial and source validation.

The window routes the request through the bounded-shooting WorkerClient, shows probe progress and readable noninterruptible stages, and keeps the GTK main loop free of the numerical worker. An accepted completion displays final burns, signed coarse residuals, strict encounter/checkpoint metrics, the exact partial-result label and false evidence flags. A diagnostic completion is shown and saveable as non-success. Cancel/error disables a new shooting report. Saving uses the self-contained exact-byte shooting report writer; its existing tests cover source mutation and atomic replacement.

No GTK, KSP, Codex tab or other project window was opened on the user's main desktop.
