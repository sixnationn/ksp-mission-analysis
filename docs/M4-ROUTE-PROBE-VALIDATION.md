# M4 reusable route-trial probe validation

The failure cases in `M4-ROUTE-PROBE-CONTRACT.md` were specified before implementation on 23 September 2026. The new core API prepares an immutable context from a complete synthetic fixture or exact runtime snapshot bytes and SHA-256, then reuses one integrated coarse planetary ephemeris for fixed-impulse trials. The trial type varies only the physical launch state, four inertial SI impulses and four body-relative targets. Route dates, roles, source, frame, epoch, integration settings and atmosphere authority remain fixed by the context.

The probe returns signed position/velocity and parking residuals at four checkpoints, burn records and total charged delta-v, Mars stay radius extrema, actual Venus closest-approach events, an optional in-window Venus event and the minimum observed Venus boundary margin. The label is `independent_nbody_coarse_trial_diagnostic_only`. A safe +0.05 m/s launch-impulse perturbation yields a measured Mars miss above the strict checkpoint budget; the unchanged strict evaluator rejects that same trial. A shifted Venus window reports a missing actual event instead of fabricating one. Nonfinite, body-centre, source, coverage and unsafe trials fail explicitly.

The runtime-shaped test checks the exact-byte/hash gate and confirms that parsed source atmosphere boundaries override caller claims. It compares repeated probes from one context and retains existing strict-evaluator tests. The probe tests failed on missing implementation symbols before code. Focused route-evaluator CTest passed 1/1 on MSYS2 UCRT and 1/1 on MSVC Debug. Local MSYS2 full CTest passed 14/14. Sol High read-only review found no remaining P1/P2 issue. [CI run 35818349177](https://github.com/sixnationn/ksp-mission-analysis/actions/runs/35818349177) passed all six Ubuntu 24.04 and Windows 2022 jobs at source commit `0e01283`, including both C++ CTest matrices and desktop build checks.

This slice is a numerical diagnostic API, not an optimizer. It does not certify Mars-stay interior clearance beyond the existing monitor limits, a feasible route, or agreement with installed KSP/Principia. It is not yet exposed through the worker or desktop UI. The next M4 slice can use these signed residuals to build a bounded shooting search, then submit every candidate that appears to meet the constraints to the existing strict fixed-route evaluator.
